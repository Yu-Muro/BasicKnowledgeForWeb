# ユーザー登録画面 `/register`

## 概要
- 新規ユーザーを作成する画面。
- 登録成功後は成功メッセージを表示する（自動ログインはしない）。

## アクセス制御
- 未ログインでも表示可能。
- 登録できるロールは `user` のみ。`admin` を指定した自己登録は拒否する。

## 画面構成
- 入力項目
  - 名前
  - 所属部署（全会期共通の部署から必須選択）
  - メールアドレス
  - パスワード
  - パスワード（確認用）
- 表示要素
  - フィールドごとのバリデーションエラー
  - サーバーエラー
  - 登録成功メッセージ

## フォームバリデーション
- バックエンドの `createUserSchema` を再利用
- `confirmPassword` はフロントで追加し、`password` 一致を検証
- 主な制約
  - `name`: 1〜255 文字
  - `email`: メール形式
  - `password`: 8 文字以上
  - `departmentId`: 存在する部署のUUID、必須

## 利用 API
- `GET /api/departments`（認証不要）で部署候補を取得する。取得中・候補なしでは登録ボタンを無効にし、取得失敗時はエラーを表示する。

### `POST /api/users`
- リクエスト
```json
{
  "name": "山田太郎",
  "email": "taro@example.com",
  "password": "password123",
  "departmentId": "uuid"
}
```
- 成功時
  - `201 Created`
  - レスポンス: `{ "user": { ... } }`
- 失敗時
  - `400`: バリデーションエラー / メール重複
  - `500`: サーバーエラー

## 実装メモ
- フロント: `apps/frontend/app/register/page.tsx`
- バックエンド: `userController.createUser` + `CreateUserUseCase`
- パスワードはバックエンドでハッシュ化して保存

## テスト観点
- 正常登録で `201`
- 部署未指定・存在しない部署・管理者としての登録は拒否
- 重複メールで `400`
- パスワード不一致（確認用）をフロントで検知
- バリデーションメッセージが表示される

登録パスワードは8〜128文字。上限を超えた入力は認証APIと共通の制約で拒否する。
