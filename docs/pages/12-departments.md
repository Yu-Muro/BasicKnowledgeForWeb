# 部署管理 `/departments`

## 概要
- 全会期で共通の部署マスタを管理する管理者専用画面。
- 会期を選択せずに追加・編集・削除できる。
- 一般ユーザーは `/dashboard` へリダイレクトされる。

## 画面構成
- 部署名の一覧と追加・編集・削除。
- 追加と編集は共通モーダルを使用し、入力エラーをモーダル内に表示する。
- キャンセル・Escape・背景クリックで閉じ、操作元へフォーカスを戻す。
- 保存中は入力・閉じる操作を無効にし、成功後に一覧を更新する。
- 過去会期からコピーする機能は廃止。

## データ構造
```ts
type Department = {
  id: string;
  name: string;
  createdAt: string | null;
  updatedAt: string | null;
}
```
- 部署名は全体で一意。

## APIとアクセス制御
- `GET /api/departments`: 認証不要。登録時の部署選択にも使用する。
- `POST /api/departments`: `auth_token(admin)` 必須。Body: `{ "name": "企画部" }`。
- `PUT /api/departments/:id`: `auth_token(admin)` 必須。Body: `{ "name": "新名称" }`。
- `DELETE /api/departments/:id`: `auth_token(admin)` 必須。成功: `{ "id": "uuid" }`。
- いずれも `x-event-id` と `event_id` は不要。
- 一般ユーザーの変更操作は `403`。対象なしは `404`、ユーザー・部屋割り・タイムテーブルから参照中の部署の削除は `409`。
- `POST /api/departments/copy` は廃止（`404`）。

## 既存データの移行
- 完全に同じ名称の部署を代表IDへ統合する。部屋割りとタイムテーブルの参照も付け替える。
- 同じ予定に同名部署のタグが複数付いている場合は1件にまとめる。
- 既存ユーザーの所属部署は管理者がダッシュボードで指定する。詳細は `docs/global-departments-migration.md`。

## テスト観点
- 未ログインの登録画面から共通一覧を取得できる。
- 会期指定の有無・会期切替で一覧が変わらない。
- 管理者だけが部署を追加・編集・削除できる。
- 参照中の部署を削除できない。
- 保存・削除後に一覧が更新される。

## 更新後の一覧取得エラー

- 保存・削除が成功し、その後の一覧取得だけが失敗した場合は、成功メッセージと再取得の案内を表示する。
- 保存済みのフォームは閉じ、削除済みの部署は表示から除く。一覧の再取得を案内し、操作を再実行させない。
